# Security review, threat model and limitations

**Status (2026-10-11):** experimental. Core paths, subagents, compaction, `/resume`, `/clear` and concurrent sessions are live-tested with synthetic data in a clean interactive Claude Code CLI 2.1.287; type-checked against 2.1.295. Redact Restore is **not** a DLP product. Do not rely on it for real secrets until the release gates at the end of this file are met.

## Goal and trust boundary

**Goal:** the model API never receives the private values; everything that runs on this machine works with the real ones. This matches what a local masking proxy such as maskit does, without changing the API endpoint or the official OAuth login.

Redact Restore runs inside the Claude Code client as a hooks module. It rewrites what the engine's documented hooks let it rewrite, before the official model connection sends anything. It is not a network boundary, so tools that forward their input to a model are kept on placeholders (`keep_tools`) instead of relying on a later re-mask.

- **Protected from:** the remote model (and Anthropic's API), on the paths marked _covered_ below.
- **Not protected from:** the local Claude Code process, its local transcript files, other installed plugins and mods, telemetry, settings hooks, the OS, and anything else on this machine.

### Fail-closed behavior on hook failure

A hook that throws, returns a bad shape or overruns its budget is skipped unless its `.catch` answers. Every gating hook has a `.catch`:

| Hook                                  | On failure                                                                         |
| ------------------------------------- | ---------------------------------------------------------------------------------- |
| `prompt.submit`                       | Prompt dropped with a message                                                      |
| `prompt.context`                      | Blocks masked without recording (no restoration, no leak)                          |
| `prompt.attachment`                   | Attachment left out (`text: null`)                                                 |
| `prompt.compose`                      | Sections masked without recording                                                  |
| `session.append`                      | Masked without recording; if that throws too, text/tool results/media are withheld |
| `turn.step`                           | Request not sent (also when the transcript cannot be read)                         |
| `tool.call` (Write/Edit/NotebookEdit) | Operation denied                                                                   |
| `ui.render`                           | No `.catch`: the engine draws its own row, so placeholders stay visible (safe)     |

## Local restoration

- **Display:** `ui.render` rewrites `UserMessage` and `AssistantMessage` text only on screen. The stored message and the model's view keep placeholders (verified in the CLI transcript).
- **Streaming (`restore_streaming`, default off):** restores placeholders in the reply's text chunks as they stream (main loop only; a placeholder split across chunks is held back until complete). The engine records rewritten stream text, so the response row briefly holds originals before `session.append` masks it again with the vault's known values. Verified live: stored assistant rows held placeholders only and the next request carried placeholders. Off by default because it relies on that re-mask.
- **Tools (`restore_mode`, default `all`):** every tool input is walked and known placeholders are restored, so `Bash`, `Write`, `Edit`, `Grep`, `Read` and local MCP tools get originals. Verified live: `echo` wrote originals to disk, `grep` matched the restored pattern, and the output came back to the model masked. An unknown placeholder denies the call.
- **Kept on placeholders (built in, `keep_tools` adds more):** `Agent`, `Task`, `Workflow`, `WebFetch` (its prompt and page go to a summarizing model), `WebSearch` (runs server-side), `SendMessage`, `Skill`, `RemoteTrigger`, `CronCreate`, `ScheduleWakeup` (later prompts or cloud agents), and `SendFeedback`, `PushNotification`, `Artifact`, `ArtifactData`, `ArtifactComments` (sent to Anthropic services). Options cannot remove these, so a misconfiguration cannot hand values to a model. Verified live: a subagent received placeholders only.
- **Refused (`deny_unrestored_tools`):** with restoration off for them, `Write`, `Edit` and `NotebookEdit` are refused rather than writing placeholder text into files.
- **Policy order:** kept tools win, then `restore_mode`, then refused tools (`hooks/policy.ts`).
- **Configuration UI:** the `/plugin` → Configure options form shows string options empty; during development the lists replaced the defaults, so typing one tool there would have dropped `WebFetch`/`Agent` from protection. Now the lists only add.

## Saved rules and the scan

- **Sensitivity is judged locally, never by the model.** Finding and classifying private values (the scan, detectors, the rule form) runs on the user's machine; the model receives counts and labels only. The bundled skills tell the model not to read files or run commands to look for private values, not to ask users to paste values, and to ask the user to run `/redact-restore scan [PATH]` instead. A model that reads a file anyway (for example because the user insists) sends every value not yet covered by a rule or detector in the clear; `KEY=value` settings are covered by the `env_assignment` detector, names and codenames are not. Live test: with the skill only, the model ran no command and no synthetic value reached it; when told to `cat .env`, the uncovered values reached it before `env_assignment` existed.

- **Plugin store:** rules added in the pane, accepted from a scan or imported are kept in `$.store`, a JSON file under the Claude Code configuration folder, in plain text. Keys are `rule.<sha256>`; dismissed candidates are `ignored.<sha256>` with no value. Values in the plugin options stay in the system keychain and are never exported. The session copy (`$.state`) is readable by other installed plugins, like the vault.
- **Scan:** runs `git config`, `git remote -v`, `git log` and `hostname` through `$.process.run` (no shell, 5 s timeout, repository hooks off) and reads `.env*` files and `package.json` in the working folder (256 KiB each). `scan PATH` reads text files under a folder through `$.fs` (skipped folders, binary files and files over 256 KiB left out; at most `scan_max_files`). Candidates are kept in session state and drawn only in the local pane; the command output carries counts by label.
- **Store failures fail closed:** if the saved rules cannot be read when a prompt is submitted, the prompt is dropped with a message (counted as a hook error), so saved values never go out unmasked. A command that fails returns fixed text, never an error message.
- **Aliases cannot unmask:** an alias that is reused or overlaps another rule's value (options or saved) is refused in the pane and imports; if one reaches the merged rules anyway, only its alias is dropped and the value is still masked with the default label. Option values carry no label or alias. Every spelling of a value is matched; rules are keyed by exact value, so case variants are separate rules.
- **`import --replace`** is refused unless every entry is valid, and writes the new rules before removing old ones.
- **Pattern rules** run on every text sent to the model, and JavaScript regexes cannot be timed out. A pattern is refused at save when it fails the checks in [Pattern rules](CONFIGURATION.md#pattern-rules): no backreferences, no nested or alternating repetition, nothing that matches empty text, and a timed run on adversarial input at growing sizes (50 ms budget). Patterns from `custom_patterns` get the same checks at session start. A pattern's example is never stored. Each pattern reports at most 1000 matches per text.
- **Command output reaches the model:** `/redact-restore` replies hold counts, labels and `~`-relative paths only, never a value or the home folder path.
- **Export files** hold originals in plain text, written where the user asks; the commands and skills warn about it.
- **Rules added mid-conversation:** earlier rows were stored before the rule existed, so the pre-send audit blocks the next request until `/clear` or `/rewind`. This is deliberate: the alternative is resending the value.

## Pre-publish review

An independent review with synthetic reproductions found and fixed: assignment and bearer values longer than 200/500 characters left their tail unmasked; a JSON-escaped private key cut off before its END line kept its body; gitleaks matches longer than the keyword window kept their tail; a custom value running into an email dropped the email's tail (and the audit then refused every request); remote and service tools (`RemoteTrigger`, `Workflow`, `SendFeedback`, …) received originals; `{{…}}`-style formats did not restore while streaming when split inside the opening mark; formats with letters at their edges skipped restoration inside words. Each has a regression test (`tests/unit/review-regressions.test.ts`).

Known and accepted: with an alias and case-insensitive matching, every case variant restores the first-seen casing; the literal-match regex is rebuilt as the vault grows (slow only with thousands of new values per session); status files are not cleaned up.

## Placeholder customization

- **Random ids stay mandatory** in `placeholder_format` (`{id}`, 8–32 hex, default 12 = 48 bits from `crypto.randomUUID`). An id only has to be unique within a session; guessing one gains nothing beyond what the model already sees, and an unknown placeholder is refused at tool calls.
- **Fixed aliases** (the rule form's Alias field) are predictable by design: the model sees the same alias every session. They hide the value, not the fact that the same value recurs. Restoration matches an alias only as a whole word; aliases that look like ordinary words, contain spaces, overlap their value, or repeat are rejected.
- Labels (the rule form's Label field) tell the model what kind of value it is; choose labels that do not themselves reveal the secret.

## Known gaps (not covered)

- Detectors: configured literals, vault values, email, the built-in table, and 212 vendored gitleaks rules ([DETECTORS.md](DETECTORS.md)). gitleaks rules are RE2 regexes run on a backtracking engine: each was timed on adversarial input at generation (9 slow rules dropped), and they run only in windows around their keywords. Not detected: names, addresses, paths, IDN emails, generic high-entropy strings without a keyword, values encoded (base64/URL/HTML/JSON escapes) or split across lines, and secrets from providers not in the table. Zero-width characters and homoglyphs inside a value can cause partial matches.
- Media: images, PDFs and documents cannot be scanned. They are withheld or refused by default; `allow_media` sends them **unscanned**.
- Model mutation: a model that changes a placeholder produces an unknown token. Writes with it are refused, and the display shows the token.
- `/resume` in a new process starts with an empty vault (observed live). Tokens in earlier history cannot be restored: the screen shows them raw and writes using them are refused. Attachments re-rendered after the resume get fresh tokens, which restore. There is no persistent vault by design.
- Concurrency: parallel dispatches (attachments render together) can mint several tokens for one value; all are recorded and restore (observed live). Separate sessions have separate vaults: a second concurrent session refused the first session's token (observed live).
- Agent teams and peer messages use the same hooks but are not live-tested.
- `sensitive: true` protects storage, but plain text is still in Redact Restore's memory, in `$.state`, and in the transcripts noted in finding 9.
- A multi-value `custom_values` list can be set only in the interactive `/plugin` → Installed → redact-restore → Configure options flow. `claude plugin configure --values-stdin` and repeated `--config` keep a single value.

## Attacker considerations

- Placeholder ids are random (`crypto.randomUUID`, 48 bits by default), not derived from the value, so a placeholder reveals nothing about its original. An unknown placeholder is refused at tool calls.
- An attacker who controls file contents or web results can steer the model (finding 3). Use `restore_mode: files` or `none` in sessions that read untrusted content, and review network-capable tool calls.
- Custom values are matched as literals, never as regex. One alternation regex per literal set is linear-time. User-supplied regex rules (future work) need ReDoS limits.
- Other mods may run before Redact Restore and read raw data. Hook order and managed settings can affect coverage.

## Release gates

Do not use real secrets until:

1. Both CLI and Desktop Code pass the round-trip tests in `docs/TEST_PLAN.md` on the installed versions.
2. You accept finding 3 (local tools act with real values), or narrow restoration.
3. Agent teams and peer messages have been live-tested if you use them.
4. The user accepts that native Mods cannot guarantee whole-process DLP.
