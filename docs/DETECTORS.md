# Detectors

Each detector labels its placeholders, e.g. `{{PRIVATE:AWS_KEY#<id>}}`. Validators keep false positives down, and only the secret part of a match is masked (the password of a connection string, the value of `password=`).

Overlaps resolve leftmost, then longest, then by rank: configured values, then provider-specific built-ins, then gitleaks rules, then the generic catch-alls (`secret_assignment`, `env_assignment`, `bearer_token`). Turn off one gitleaks rule with `disable_detectors: gitleaks.<rule-id>`.

The gitleaks table is generated, not hand-written: `bun scripts/sync-gitleaks.ts [tag]` fetches the pinned release, converts Go RE2 syntax to ECMAScript `RegExp` syntax (the regex engine TypeScript uses), drops rules that do not compile or run slowly on adversarial input (listed in the generated header), and copies the license to `hooks/vendor/LICENSE-gitleaks.txt`. A hooks module cannot import npm packages, so third-party rules are vendored this way.

Rules come from [gitleaks](https://github.com/gitleaks/gitleaks), [claude-code-redact](https://github.com/karanb192/claude-code-redact), [maskit](https://github.com/xiaYuTian11/maskit) and [Presidio](https://github.com/microsoft/presidio). The table lives in [hooks/detectors.ts](../hooks/detectors.ts); a new detector is one entry with an id, a label, groups, a default and a finder.
